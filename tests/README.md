# Проверки PM English

Запускать из корня репозитория. `npm ci` устанавливает зафиксированные версии dev-зависимостей (Node.js 20+). Обычный статический сайт не требует npm или сборщика. Для browser-наборов запустить `npm run dev` в другом терминале; нужны Playwright и Chromium.

## Быстрые проверки

```sh
npm run check
npm test
npm run format:check
```

`check` проверяет маленькую HTML-оболочку без встроенных CSS/JS/base64, существование и уникальность подключений, `defer`, версии URL, синтаксис скриптов и отсутствие повторных публичных функций. Unit-набор запускается последовательно: тест генератора записывает карьерные файлы для проверки детерминизма.

| Файл                                    | Что проверяет                                                                                                           |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `unit/structure.test.cjs`               | Оболочку, структуру загрузки, контрольные суммы frozen baseline/картинок и полноту каталога файлов архитектуры          |
| `unit/career-content.test.cjs`          | Контракты 470 кейсов / 678 шагов, рубрику, факты, ID, планы, максимумы и детерминированную генерацию пяти файлов треков |
| `unit/practice-data.test.cjs`           | 15 Additional, три механики, ключи и независимые расчёты                                                                |
| `unit/career-practice.test.cjs`         | 42 Product-варианта, реальные слоты, зависимости, метрики и сохранность пилота                                          |
| `unit/project-career-practice.test.cjs` | 42 Project-варианта, Гант, окна, выполнимость планов и сохранность Product                                              |

Для другого сервера передать `CAREER_URL` (в некоторых наборах `PRACTICE_URL`). Для другого Chromium — `CHROMIUM_PATH`. Тесты сохраняют диагностические снимки в `/tmp/` и не требуют сохранения результатов в Git.

## Baseline и генерация

`build-career.cjs` читает `content/baseline.json` с исходным контрактом коммита `a55e1ced315c6e73e2bcb1aa6cde55fd4bd044b1`. Файл был извлечён из этого Git-объекта один раз, а его контрольная сумма закреплена в unit-тесте. Обычные генерация и unit-тесты больше не разбирают старый HTML и не требуют его Git-объекта. Запуск: `npm run build:content`, затем `npm test`.

Для дифференциальных проверок структуры нужен также baseline `c6d5a78344c40e8e5ff0f1a005a53d97875b0d00`. `helpers/baseline-site.cjs` отдаёт его файлы локально прямо из Git, без изменения рабочей ветки; `helpers/assets.cjs` читает реальный список карьерных скриптов из текущего HTML.

Не подменять baseline текущими файлами ради прохождения проверки. Не перезаписывать старые проверки математических ключей проверками только собственного ответа.

## Границы проверок

Browser-наборы блокируют внешние fonts/Firebase для воспроизводимости. Они проверяют локальное сохранение и функцию слияния, но не подтверждают настоящий Firebase-login, cloud round trip, аппаратный микрофон или физические iOS/Android-устройства. При изменении этих интеграций нужны отдельные проверки.

## Офлайн-регрессия

`npm run test:browser:offline` запускает собственный HTTP-сервер под `/pm-english/` и настоящий service worker в Chromium. Проверяет полную загрузку, открытие при отключённой сети, прохождение Additional в каждом из пяти треков нажатием кнопок, сохранение/reload, мобильную ширину и активацию обновления после закрытия старого окна с очисткой только старого кеша. `unit/offline.test.cjs` проверяет свежесть SHA-256 манифеста и отсутствие блокировки локальных сохранений зависшей/ошибочной облачной записью, повторную отправку и uid. Физические телефоны и реальный Firebase не используются.

Исторический `test:browser:parity` сравнивает интерфейс до реорганизации; новый блок Offline learning на Progress — ожидаемое изменение интерфейса и не обязан совпадать с историческим скриншотом.
